# Run Directory Contract

Every relay run lives in its own directory. Nothing inside a sealed round directory is ever
modified again. This file is the single source of truth for paths; `scripts/relay_run.py`
implements it and `SKILL.md` relies on it.

## Location

```
<workspace>/relay-runs/<YYYYMMDD-HHMM>-<slug>/
```

- `<workspace>`: the current working directory of the host agent (override with `--root`).
- `<slug>`: 2-6 lowercase ASCII words joined by `-`, derived from the task title
  (e.g. `readability-ai-article`, `fix-login-timeout`). Non-ASCII titles get a short
  romanized or English slug chosen by the orchestrator.

## Layout

```
<run>/
├── task.md                 # goal, constraints, task type, slots, language, input stats
├── 00-original/            # untouched input (files copied here; pasted text saved as input.md)
│   ├── <original files...>
│   └── MANIFEST.md         # list of files + char counts (generated by relay_run.py init)
├── r1-<modelA>/            # round 1, written ONLY by model A
│   ├── draft.<ext>         # full revised content (no commentary)
│   └── notes.md            # structured notes (see "notes.md headings")
├── r2-<modelB>/            # round 2, written ONLY by model B
├── r3-<modelC>/            # round 3 (finalizer), written ONLY by model C
├── final/                  # created by the finalizer round
│   ├── FINAL.<ext>         # copy of r3 draft (or the agreed final draft)
│   └── SUMMARY.md          # what changed across all rounds, open questions, how to use
├── exec/                   # OPTIONAL step 4 (code tasks only)
│   ├── plan.md             # what the executor was told to do
│   ├── result.md           # executor's report (files touched, commands run, test output)
│   └── verify.md           # verifier's report
├── REPORT.md               # generated by relay_run.py report
└── log.jsonl               # one JSON line per event (round start/end, seal, retry, error)
```

### Naming rules

- Round directories: `r<N>-<model-id>`; `<model-id>` is the exact model identifier with `/`
  and whitespace replaced by `_`. Example: `r1-claude-opus-5-5`, `r2-gpt-6-astra`.
- Retry of a failed round: `r<N>-<model-id>-retry1`. The failed directory is kept for
  forensics; `log.jsonl` records which directory is authoritative.
- `draft.<ext>` keeps the extension of the primary input (`.md`, `.txt`, `.py`, ...).
  Multi-file inputs (code tasks) use `draft.md` as the solution document; actual code
  changes happen only in step 4 (`exec/`).
- Round numbering is 1-based and follows the configured `rounds` order, not the slot letter.

### Immutability ("never overwrite earlier drafts")

Three independent guards, all enforced by `relay_run.py`:

1. `next-round` refuses to return a directory that already exists (suggests `-retryN`).
2. The sub-agent prompt contains exactly one writable path (its own round directory).
3. `seal` records `sha256` of every file in the round directory into `log.jsonl` and sets the
   files read-only (`chmod a-w`, best effort). `verify` re-hashes and reports tampering.

## task.md format

```markdown
# Relay Task

- **Title**: <short title>
- **Task type**: article | requirement-doc | code-solution | generic
- **Goal**: <one or two sentences, the optimization target>
- **Constraints / red lines**: <bullet list; "none" allowed>
- **Output language**: zh | en | <other> (default = language of the original)
- **Rounds**: A -> B -> C
- **Slots**:
  - A: <model-id> (effort: high)
  - B: <model-id> (effort: high)
  - C: <model-id> (effort: high)  <- finalizer
- **Executor** (optional): <model-id> | none
- **Verifier slot**: C
- **Backend**: agent | script
- **Input**: <N> file(s), <M> characters total
- **Created**: <ISO timestamp>
```

## notes.md headings (required, in this order)

```markdown
# Round <N> notes — <model-id>

## Assessment
## Changes Made
## Rejected
## Open Questions
## Handoff
```

- **Assessment**: 3-8 bullets on the incoming draft against the goal and review dimensions.
- **Changes Made**: numbered list, each item = `where` + `what` + `why`.
- **Rejected**: suggestions or earlier changes deliberately NOT adopted, with reasons.
  The finalizer MUST list rejected changes from r1/r2 here.
- **Open Questions**: things only the human can decide. "none" allowed.
- **Handoff**: <= 150 words. The ONLY part the orchestrator reads back into its own context
  and the part forwarded to the next round as "previous notes summary" if the full notes are
  too long.

## log.jsonl events

```json
{"ts":"...","event":"init","run":"...","task_type":"article","rounds":["A","B","C"]}
{"ts":"...","event":"round_start","round":1,"slot":"A","model":"...","effort":"high","backend":"agent","dir":"r1-..."}
{"ts":"...","event":"round_end","round":1,"status":"ok","chars":12345,"duration_s":87.2}
{"ts":"...","event":"seal","dir":"r1-...","files":{"draft.md":"sha256:...","notes.md":"sha256:..."}}
{"ts":"...","event":"retry","round":2,"reason":"timeout","dir":"r2-...-retry1"}
{"ts":"...","event":"error","round":2,"message":"..."}
{"ts":"...","event":"calls","paid_calls":3,"planned_calls":3}
```

Never log API keys, full prompts, or full drafts.
